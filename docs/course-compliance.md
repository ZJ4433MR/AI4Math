# 课程要求与实际实现对应

本说明按课程《数学创造性（2）》第 6 页的数学研究流程，以及第 17 页的智能体组成核对。用户最初提供的 A 问题方案用于 LABS 专用案例；后来明确要求的可输入新问题、真实运行并持续迭代，由 `general-v1` 通用工作流实现。课程材料和方案是验收依据，不是已经完成的实验记录。

## 可以运行的研究闭环

用户提供自然语言问题、前提和目标。运行时模型选择研究计划、猜想、实验程序、形式化表述和证明尝试，宿主执行所选工具，将实际结果和模型审查意见送入下一轮。题目和答案不再固定为 LABS，也没有把两个示例的计划写成控制器分支。

工具能力与资源限制仍由程序定义；“通用”指能够接收新主题、生成新实验并使用新的数学表达式，不表示能解决任意数学问题。

| 用户/课程要求 | 实际实现 | 可审查位置与边界 |
|---|---|---|
| 给定数学研究主题，自主制定研究方案 | 自然语言 `Problem` 输入；模型返回 `plan`，后续可继续调整计划 | `solve --problem`、`--problem-file`；`general/schema.py`、`general/controller.py` |
| 开展背景调研 | 模型选择查询词和来源，检索 arXiv 或 Crossref；原始响应保留 | `general/literature.py`；只读取元数据和摘要，不能等同于读完论文 |
| 提出猜想并评价其质量 | 模型提出带自然语言陈述的命题，审查角色给出清晰性、意义、可处理性评分及局限 | `hypotheses`、逐轮 `review`；质量评分是模型判断，不能认证新颖性 |
| 编写和运行数学实验 | 模型提交新的 Python 程序，独立子进程运行并保存代码、结果、输出、资源限制 | `general/experiment.py`、`tools/*/code.py`；产物标为 `empirical_unverified` |
| 寻找反例、根据失败修改猜想 | 精确有限检查或新编程序寻找见证；`revise` 必须引用父命题，保留旧命题和证据 | `parent_id`、`evidence_ids`、`formal_result_history`；反例必须对应原命题的前提和量词 |
| 尝试证明并核验 | 保存自然语言证明草稿；符号工具检查新有理函数恒等式，归纳工具检查新多项式求和公式 | `general/math_tools.py`；前者仍是草稿，机器证书只覆盖明确的形式化范围 |
| 根据真实反馈迭代研究 | 下一次 proposer 输入包括工具证据、最近错误和上一轮 critic 的反馈 | `calls/*/context.json` 的 `evidence`、`last_review`；没有固定的题目解题顺序 |
| 展示研究过程并形成报告 | 本地页面启动真实后台研究、显示已保存进展；封存后离线生成 HTML/Markdown 报告 | `general/web.py`、`general/report.py`；查看旧记录与启动新研究明确区分 |
| 数学结果可追溯、可复核 | 保存调用、行动、见证、代码、状态、预算与源码哈希；复核受支持的数学证书 | `manifest.json`、`verify --run-dir`；哈希完整性不能代替数学证明 |
| 保留 A 问题研究成果 | 原 LABS 工具、专用控制器、真实运行、对照数据和 PDF 保留；通用流程通过 LABS 插件调用它们 | `agent/`、`math/`、`search/`、`results/research/`、`results/evaluation/`；不改写旧证据为新研究 |

## 第 17 页的智能体组成

| 组成 | 本项目的对应实现 |
|---|---|
| 模型 | 真实 Codex CLI 或已配置 API 后端；proposer 与 skeptic 使用不同角色提示，并非两个独立训练的模型 |
| 编排 | 校验结构化行动，执行工具，提交实际结果供审查，再将反馈传回下一轮 |
| 能力 | 文献检索、新生成程序、精确有限检查、符号恒等核验、多项式归纳核验、LABS 插件 |
| 状态 | 原始问题、研究计划、命题及修订关系、证据、审查、错误、累计预算和停止原因 |

执行前先封存工具成本预留；中断后不能清零预算。续跑要求原问题、模型、资源配置和源码一致；报告保留失败、负结果及未解决部分。`dry_run` 是离线接线测试，不能充当真实模型研究。

## 三个非 LABS 的真实运行

以下会话均使用 `live / codex_cli`，manifest 中 `answers_preloaded=false`。前两个记录生产源码版本 `30e8528`，第三个记录版本 `5a412b0`。这只说明宿主没有加载预先计算的答案，不表示模型没有相关预训练知识。经典结论的复现与核验不能写成原创定理。

- 整数立方和：`results/general/2026-10-09T173120.080994_0000`，已完成 7 轮、14 次后端启动尝试。第 1 轮模型原计划先检索，critic 要求先独立生成数据；第 2 轮模型改为写程序累计整数和与立方和，`EV002` 保存 `n=1..20` 的实际数据。随后提出猜想，并分别提交 `EV004` 的整数和归纳证书和 `EV005` 的立方和归纳证书，基例与归纳差分均精确归零。单独的立方和证书没有覆盖整个复合陈述，审查要求结合整数和证书；结尾明确说明只做了 `1..20` 的实验，没有声称完成更大范围检查。
- 多项式生成素数：`results/general/2026-10-09T173130.851756_0000`，已完成 11 轮、22 次后端启动尝试。研究对象由问题输入指定为 `n**2+n+41`，不是旧 LABS 命题菜单。模型新写 `0..1000` 的试除与分解程序，但 `EV002` 真正触发操作上限、没有结果；收到失败审查后，`EV003` 改写程序并缩小到 `0..40`。`EV004` 独立精确检查 `0..39` 的素性，`EV005` 核验 `n=40` 的值为 `1681=41²` 且非素数。`EV006` 的一般证明缺少“取值互异”论证，critic 指出后，`EV007` 加入 `f(n+1)-f(n)=2n+2>0`。`EV008` 只认证因式分解及相邻差恒等式；审查指出没有认证真因子不等式、递增性及无穷性，模型在 `EV009` 建立父命题为 `H003` 的 `H004`，把认证声明缩小为三个恒等式，保留完整一般证明为未获机器认证的候选。第 11 轮如实说明没有完成 `0..1000` 探索，也不声称素数取值有无穷多个。
- 二维向量长度、内积与面积：`results/general/2026-10-09T173914.153710_0000`，直接输入一个新的 CLI 主题，已完成 8 轮、16 次后端启动尝试，命令退出码为 0。模型新写 `itertools.product` 程序，在 `EV002` 实际检查 `[-3,3]^4` 的 2,401 个整数赋值；这些输出仍标为经验产物。`EV003` 精确认证 `(a²+b²)(c²+d²)=(ac+bd)²+(ad−bc)²` 对任意四个实数成立，包含零向量，没有非零排除条件。`EV006` 另在 `[-5,5]^4` 完整检查 14,641 个整数赋值上的平方形式柯西施瓦茨不等式。模型把该有限不等式检查关联到恒等式命题 `H001`，critic 明确判定范围不对应；模型随后在 `EV007` 单列 `H002` 的不等式及等号条件，保留平方非负、平方根性质、实数序与线性相关刻画为尚未机器认证的自然语言证明步骤。`EV003` 的原有恒等式证书仍保留在证据和历史中，不能把后来的有限检查或错配标记解释成它被反驳。

实际调用上下文也已检查：三个会话的第一次 proposer 输入均没有证据和命题；此后的全部 23 个 proposer 上下文，其 `last_review` 均与上一轮实际审查一致，并包含上一轮证据。三个会话合计保存 26 轮、52 次后端启动，调用元数据均记录 accepted，封存产物哈希一致。三组程序及题目各不相同，失败预算、证明缺口和证书范围真正改变了后续行动；这比只检查控制器存在循环更能说明研究过程发生了迭代。后端启动次数不是可直接观测的 provider 内部请求数或实际费用，后者未知时仍记录 `unknown`。

立方和会话的研究状态已经是 `finished`，数学证书复核通过，但当时命令进程在随后打印含 `³` 的摘要时遇到 Windows GBK 编码错误、退出码为 1。研究完成状态与终端显示错误须分开报告，不能把该退出码隐藏，也不能改写已保存的数学证据为研究失败。后续源码 `5a412b0` 修正了 CLI UTF-8 输出与直接调用的显示兼容性，并为 Windows 原子替换后的短暂读取占用增加有限重试；原运行仍保留 `30e8528` 的生产版本信息，不事后重写。

## 课堂演示与结论边界

新问题的真实运行命令：

```powershell
.\.venv\Scripts\python.exe -m ai4math_agent solve --problem "研究前 n 个正整数的五次方和，自主设计实验、提出公式并尝试证明" --backend codex_cli --max-rounds 12
.\.venv\Scripts\python.exe -m ai4math_agent serve
```

已完成会话的证据复核命令：

```powershell
.\.venv\Scripts\python.exe -m ai4math_agent verify --run-dir results/general/实际会话目录
```

本地界面输入不同问题后点击“启动实际研究”，才会发生新的模型调用与数学实验。浏览已有报告或播放原 LABS 日志没有产生新的研究；留出评价中的 `agent_policy` 执行冻结策略，也不是每次实验都重新询问模型。

形式化证书与原自然语言命题分开记录。`formal_status` 和 `verification_scope` 描述核验了什么；`semantic_alignment` 是模型的对应判断，明确标记不具备独立证明效力。有限域或采样结果不能推广到无限域；不支持的证明、失败的实验和预算耗尽都应保留为明确局限。

当前证明工具主要支持精确有理数/模运算的有限命题、有理函数恒等式和多项式求和归纳，不是完整的定理证明器；未集成 Lean、任意领域的证明搜索、论文全文阅读或模型训练。生成程序执行器有语言策略、子进程和资源约束，但不是操作系统安全沙箱。

这三个经典题目展示运行能力和反馈闭环，不证明能自动创造新数学结论。原 LABS 案例展示开放问题中的有限结构研究与可靠候选，仍未解决 LABS 渐近开放问题。课程是否得分和研究质量由教师结合题目、证据与演示判断，本说明不把架构存在等同于自动满足全部评分标准。
